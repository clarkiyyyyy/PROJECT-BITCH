Foundations

Why Multithreading Matters

Modern applications rarely do only one thing at a time. A browser renders a page while downloading assets, an editor saves a file while you keep typing, and a server answers one request while another is still being processed. Multithreading is the mechanism that makes this overlapping work possible inside a single program.

01

Responsiveness

Background operations can run without freezing the main application.

02

Resource Sharing

Threads belonging to the same process can efficiently share memory and resources.

03

Concurrency

Multiple tasks can make progress during overlapping periods of execution.

Scheduling

What is a Context Switch?

A context switch happens when the operating system pauses the execution of one thread or process and allows another one to run. The paused execution context is stored so it can be resumed later exactly where it stopped.

TIME →
Thread A
RUN WAIT RUN
Thread B
WAIT RUN WAIT
t0 t1 t2 t3

Thread switches are generally lighter than process switches because threads within the same process share memory and resources. The system does not need to swap page tables or reload an entire address space, so less work is required to pause one thread and resume another. Process switches are more expensive for exactly the opposite reason: each process owns a separate address space that must be preserved and restored.

Shared Data

Synchronization & Shared Data

When multiple threads access shared mutable data, synchronization mechanisms are used to avoid inconsistent results.

Mutex / Lock

Allows only one thread at a time to access a protected section.

Semaphore

Controls how many threads may access a resource simultaneously.

Condition

Allows threads to wait until a particular condition becomes true.

Event

Provides a simple signal that threads can wait for.

Two threads reaching one protected resource

Thread A LOCK SHARED DATA LOCK Thread B

Only one thread can hold the lock at a time, so reads and writes to the shared data happen one after another instead of interleaving unpredictably.

Failure Mode 01

Race Condition

A race condition occurs when the result of a program depends on the unpredictable timing of two or more threads.

Shared value: counter = 10

  1. Thread A reads 10
  2. Thread B reads 10
  3. Thread A adds 1 → 11
  4. Thread B adds 1 → 11
Expected 12
Actual 11

Both threads perform a read, an addition, and a write. Because thread B reads the value before thread A has written its result, the second increment is applied to the original value instead of the updated one. The lost update is silent: no error is raised, the program simply produces the wrong answer.

This happens because both threads read and modify shared data without proper synchronization.

Shared mutable data should be properly synchronized when multiple threads can modify it.

Failure Mode 02

Understanding Deadlock

A deadlock is a situation in which two or more threads are permanently waiting for resources held by each other, so no thread can continue.

THREAD A

holds Lock 1

waits for Lock 2

DEADLOCK

Circular wait · no thread can proceed

THREAD B

holds Lock 2

waits for Lock 1

Four necessary conditions

  1. 1 Mutual Exclusion
  2. 2 Hold and Wait
  3. 3 No Preemption
  4. 4 Circular Wait

A deadlock can only happen when all four conditions hold at the same time. Breaking any single one of them prevents the situation.

Quick Distinction

Race Condition vs Deadlock

Race Condition

  • Threads continue executing
  • Result depends on execution timing
  • Can produce incorrect data

Deadlock

  • Threads stop making progress
  • Threads wait for one another
  • Program may appear frozen

Practical Example

Multithreading in Python

Python provides the threading module for creating and managing threads. The example below starts five workers, waits for each of them, and only then prints the final message.

worker_threads.py 
import threading
import time
import random

def worker(thread_id):
    delay = random.randint(1, 3)
    time.sleep(delay)
    print(f"Thread {thread_id} finished")

threads = []

for i in range(5):
    thread = threading.Thread(
        target=worker,
        args=(i + 1,)
    )
    threads.append(thread)
    thread.start()

for thread in threads:
    thread.join()

print("All threads completed.")
  1. 1 Five thread objects are created.
  2. 2 start() begins each thread.
  3. 3 Each worker waits for a random period.
  4. 4 The worker prints its ID when finished.
  5. 5 join() makes the main thread wait for every worker.
  6. 6 The final message appears only after all workers have finished.

Because every worker sleeps, the five tasks overlap in time. The total runtime is close to the longest single delay rather than the sum of all delays — that is the practical benefit of concurrency for waiting tasks.

CPython Internals

The Python GIL

In standard CPython, the Global Interpreter Lock allows only one thread at a time to execute Python bytecode. Because of this, threads in a single Python process take turns running Python code rather than executing it at the same instant on different cores.

Threading fits I/O-bound work

While a thread waits for data to arrive, it releases the GIL, so other threads can run. That makes threading especially useful for tasks that spend most of their time waiting:

  • Network requests
  • File operations
  • Database access
  • Waiting for external services

Multiprocessing fits CPU-bound work

For CPU-intensive tasks, multiprocessing can often make better use of multiple CPU cores, because each process runs its own interpreter with its own lock. Threads are still not useless here — they can overlap computation with I/O — but they will not speed up pure computation on their own in standard CPython.

Choose based on what the task waits for: waiting on devices favors threads, heavy arithmetic favors separate processes.

States

Thread Lifecycle

A thread moves between a small set of states from the moment it is created until it finishes.

  1. NEW

    The thread object exists, but it has not started running yet.

  3. READY

    The thread is eligible to run and waits for the scheduler to give it CPU time.

  5. RUNNING

    The scheduler has selected the thread and its instructions are being executed.

  7. WAITING / BLOCKED

    The thread cannot continue until an event occurs, such as I/O finishing or a lock being released.

  9. READY

    The blocking event has finished, so the thread becomes eligible to run again.

  11. RUNNING

    The thread resumes execution from where it was paused.

  13. TERMINATED

    The thread has finished its work and its execution context can be released.

Habits

Multithreading Best Practices

A short checklist to keep concurrent code predictable and easy to reason about.

  • Keep critical sections small.
  • Protect shared mutable data.
  • Avoid unnecessary locks.
  • Always consider race conditions.
  • Acquire locks in a consistent order.
  • Release resources properly.
  • Use thread.join() when completion must be guaranteed.
  • Prefer simple synchronization designs.
  • Test concurrent code under different timing conditions.
  • Use multiprocessing when CPU parallelism is required.

Self-Test

Check Your Understanding

Answer each question first, then reveal the model answer.

  1. Why is switching between threads generally lighter than switching between processes?

    Threads of the same process share memory and resources, so the operating system does not need to swap page tables or restore a whole address space. A process switch must preserve and reload separate memory, which takes more work.

  2. What is the main difference between a race condition and a deadlock?

    In a race condition threads keep running but the result depends on timing and may be wrong. In a deadlock threads stop making progress because each waits for a resource held by the other, so the program may appear frozen.

  3. Why is synchronization needed when threads modify shared data?

    Without synchronization, a thread can read a value, another thread can change it, and the first thread writes back an outdated result. Locks force the read-modify-write sequence to happen as one indivisible step, keeping the data consistent.

  4. What does join() do in Python?

    join() blocks the calling thread until the target thread finishes. The main thread uses it to guarantee that every worker has completed before it continues, for example before printing a final message.

  5. Why is threading often useful for I/O-bound workloads?

    During I/O the thread waits for a device, network or database and releases the GIL, so other threads can run. Several waiting operations therefore overlap, and the total time is closer to the slowest single operation than to their sum.
